# 项目设计与实施思路

项目从交付要求出发，将内容生成、预算与时间约束、执行状态分别建模。主题理解、文案和替代方案由模型判断，金额、排期、依赖、权限及保存条件由程序校验，使决策具有灵活性，结果具有可核查依据。

先完成三栏工作台，明确需求输入、计划确认、工具展示和方案阅读方式，再据此确定接口与状态结构。随后使用本地Qwen3接通需求识别、MCP调用、估算和保存，建立最小端到端流程，再补充费用账本、缓存、产物复用和恢复，接入DeepSeek与Tavily。

架构采用LangGraph双图，将对话控制与耗时执行分开，独立worker处理任务，PostgreSQL保存业务事实。MCP统一工具调用，Skill提供任务规范，确定性规则保留在业务服务中，减少重复实现。

重规划以实际反馈为依据，替代方案必须重新估算。失败重试建立新记录，成功产物按有效性复用，旧失败状态保留；重复提交和保存通过幂等约束控制，未知费用不填零。

验证覆盖规则、数据库、协议、真实模型和浏览器，重点检查缺项、超预算、工具故障、重复执行与续跑。通过故障注入核对预算、依赖、产物保留和前后端一致性，保留修复前后记录。首版限定两种制作套餐，优先完成约束处理和可靠交付。
