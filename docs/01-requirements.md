# 需求

## 要解决的问题

运营人员需要在有限预算和时间内做出一份内容活动方案。这个项目把需求收集、素材检索、文案生成、估算和保存放在同一个聊天工作台中，减少在多个工具间整理结果的工作。

输出不只有一段文案，还包括制作计划、排期、成本明细、素材来源和各步骤的结果。做不完时，应说明哪里受阻、还缺什么，以及哪些结果已经保留。

## 输入与输出

必填项是主题、制作预算、截止日期与时刻。渠道、受众、开始时间、是否必须使用真实素材可以补充。含糊的预算或时间需要追问，不由模型替用户决定。

方案包含目标、受众与渠道假设、内容策略、制作清单、脚本、素材引用、排期、成本和执行结果。保存后可以阅读全文，或下载 Markdown、JSON。

## 业务规则

预算以模拟单位计算，只约束最终方案的制作成本。工具调用和模型费用另列。制作项采用 premium/simple 两种套餐，成本与工期来自[规则表](../data/production-rules.json)。

截止时间约束制作和活动执行的完成时间，不是 Agent 的运行超时。排期使用北京时间、自然小时、单团队串行规则；未指定开始时间时从当前时间起算。

计划生成后先展示，只有明确的执行消息才启动任务。缺少信息、否定、引用“开始”或询问如何执行，都不构成授权。执行中的修改在当前工具结束后生效；新计划仍需确认。

估算超限后，模型需要依据工具结果选择替代，再次估算。预算10、初始成本12、替代成本8是固定验收用例。没有可行候选时报告未完成与已知缺口，不能改写预算或强行保存。

工具失败后保留原尝试。重试建立新记录，成功结果可以在仍有效时复用。必须真实来源的任务不允许用合成素材代替完成。重复消息和已完成计划不应重复执行或保存。

## 验收

| 场景 | 要求 |
| --- | --- |
| 正常完成 | 工具实际执行，保存方案满足预算和截止时间 |
| 缺预算或截止时间 | 一次列出缺项，不启动执行 |
| 工具失败 | 如实记录失败，有限重试、调整或停止，保留成功结果 |
| 预算超限 | 重规划后复算；无可行解时给出缺口 |
| 重复执行 | 不重复业务调用、记账或保存 |
| 失败续跑 | 沿用原运行，恢复需要继续的步骤，保留尝试历史 |
| 状态与依赖 | 每个成功步骤都有对应结果；完成状态有实际保存记录 |

测试输入、结果和 Trace 见[案例导航](../examples/README.md)，详细覆盖见[测试报告](03-evaluation.md)。

## 范围

前端为桌面优先的三栏 Web 应用，窄窗口切换聊天与方案。历史栏只提供新建和切换；任务操作通过聊天完成。工具卡片始终展开，右侧展示版本、费用与完整文档。

项目供本地单用户使用，不做登录。支持合成资料及 Tavily 文本搜索，不包含真实媒体生成、外部发布、付款和商业报价。模拟排期不是现实团队的交付承诺，文案发布前需要人工审校。
